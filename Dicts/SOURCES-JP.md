# 日本語・韓国語辞書ファイル

他の言語：[中文](SOURCES.md) ｜ [English](SOURCES-EN.md) ｜ [한국어](SOURCES-KO.md)

本ディレクトリで追加した辞書は、既存の中国語辞書と同様に UTF-8 の `.txt` テキストで、形式は「語句、入力コード、重み」を実際のタブで区切ったものです。`PinyinDict` の「辞書を読み込んで適用」で適用し、続けて「索引を再構築」を実行します。プレハブの `JapaneseDictionary` と `KoreanDictionary` は下の表の `japanese_mozc_common.dict.tsv.txt` と `korean_nikl_common.dict.tsv.txt` に接続済みです。重みは省略可能（既定は 0）で、非負整数、RIME で一般的なパーセント（`luna_pinyin` の `99.93%` など）、小数に対応し、パーセントと小数は取り込み時に 1/100 精度で整数に拡大します。

| ファイル | 用途 |
| --- | --- |
| `japanese_mozc_common.dict.tsv.txt` | 日本語のコンパクト版。変換重みの上位 30,000 個の語句/コードの組。まずこちらで試してください |
| `japanese_mozc.dict.tsv.txt` | 日本語の完全変換結果。より多くの語形と固有名詞を収録。**警告：語句数が多すぎるため、直接の使用は推奨しません。** |
| `korean_nikl_common.dict.tsv.txt` | 韓国語の等級付き語句から重み上位 10,000 個の語句/コードの組。まずこちらで試してください |
| `korean_nikl.dict.tsv.txt` | 韓国語基礎辞書の完全変換結果。等級なしの語句も含みます。**警告：語句数が多すぎるため、直接の使用は推奨しません。** |

「辞書を読み込んで適用」は接続されたソースファイルを解析し、語句と重みを独立辞書アセットに書き込みますが、索引は構築しません。続けて同じコンポーネントのインスペクターで「索引を再構築」を実行すると、同じアセットに整列済み索引が書き込まれます。両方の手順はメニューからも実行できます：`Tools → HXIME → Simplified Chinese / Traditional Chinese / Japanese / Korean → Load and Apply Dictionary` と対応する `Rebuild Lookup Index`、または `Tools → HXIME → Load and Apply All Dictionaries`、`Tools → HXIME → Rebuild All Lookup Indexes`。解析段階では処理済み行数を表示し、Console は `[HXIME Dictionary Import]` として段階ごとの所要時間を記録します。これらの表示は完全版辞書の読み込みを速くするものではありません。

すべての辞書は `Assets/HXIME_DictionaryData/` 内の独立したバイナリ `.asset`（例：`SimpDictPool.asset`）に保存されます。まず「辞書を読み込んで適用」が語句を書き込み、次に「索引を再構築」が同じアセットへ整列済み索引を書き込みます。プレハブとシーンは辞書データも索引配列も受け取らず、プレハブは辞書ソースファイルを接続するだけです。アセットはユーザー自身のプロジェクトで生成され、パッケージには含まれません（同梱されるのは本ディレクトリのソーステキストです）。再読み込みでは新しいアセットが作成されるため、以前のアセットの他の参照先には影響しません。Play モード進入時とワールドビルド時に、エディターがアセットの語句と索引を Udon に書き込みます。読み込みまたは索引が不足している場合は Play モード進入がキャンセルされ、ワールドビルドは失敗します。大きな配列のプレハブオーバーライドは避けられ、ある言語の読み込みと索引構築を終えた後の実行時検索性能は従来と同じです。

「完全」とは以下のフィルタ規則を経た完全な結果を指し、元データのすべてを含むものではありません。正確な行数・バイト数・SHA-256・上流のコミット番号・各ソースファイルの URL は `dictionary-manifest.json` にあります。コンパクト版は人手で校閲した高頻度語リストではありません。現在のエンジンは整列済み索引で検索するため、対象の VRChat プラットフォームでの遅延確認は引き続き必要です。

## 日本語の出典と処理

- 出典：Google Mozc、`src/data/dictionary_oss/dictionary00.txt` 〜 `dictionary09.txt`。
- 固定リビジョン：[`13c98988247aa711d99db9e348ec2a597d14b5cd`](https://github.com/google/mozc/tree/13c98988247aa711d99db9e348ec2a597d14b5cd/src/data/dictionary_oss)。
- 元の行から読み、出力語句、語コストを抽出します。コードは pykakasi 2.3.0 の Hepburn 出力を使って**元の仮名読み**から生成し、漢字から読みを推測することはしません。
- 処理対象は完全なひらがな・カタカナ・長音符のみで構成される読みに限ります。数字・記号を含む読みやラテン文字コードに変換できない読みは除外します。コード内の `'` と `-` は許可します。
- 重みは `max(1, 40000 - 元のコスト)` で、元のコストが低いほど変換重みが高くなります。これは並べ替え用の近似値であり、語頻度ではなく、Mozc の品詞連接コストや文解析能力は含みません。
- 「出力語句、コード」で重複を排除し、最大の重みを残します。プロジェクト既存の日本語例（重み 50,000）を追加します。さらに重み上位 30,000 組を選んでコンパクト版とします。
- コードは変換器の長音・撥音などの規則を保ちますが、すべての入力方式の別名を網羅するものではありません。例：`nihongo` → `日本語`、`toukyou` → `東京`。自動変換結果は 1 件ずつ人手で校正していません。

## 韓国語の出典と処理

- 原作者：韓国国立国語院（국립국어원 / National Institute of Korean Language）。データセット：[한국어기초사전 / Korean Basic Dictionary](https://krdict.korean.go.kr/)。
- ダウンロード元：コミュニティ管理の [`spellcheck-ko/korean-dict-nikl`](https://github.com/spellcheck-ko/korean-dict-nikl/tree/42c0d01889f34536e9cf94fe57f62bd2055b1bde/krdict)、固定コミット `42c0d01889f34536e9cf94fe57f62bd2055b1bde`、`krdict/001.xml` 〜 `011.xml`。このミラーは国立国語院が公式に管理しているものではありません。
- 抽出するのは韓国語の見出し、テキスト発音、語彙等級のみで、原文の例文・語義・音声その他のメディアは再配布しません。
- 解析前に XML 1.0 が受け付けない制御文字を元の XML から除去し、件数をマニフェストに記録します。ダウンロードしたファイル自体は変更しません。
- ハイフンで始まる/終わる接辞、単独の字母、純粋な韓国語でない見出しは除外します。見出し内部のハイフン区切りは除去し、`^` は出力の空白に変換します。
- korean-romanizer 0.28.0 で見出しからローマ字コードを生成します。処理可能なテキスト発音がある場合は発音コードの別名も生成します。コードは空白を除去して小文字化し、出力語句は語間の空白を保ちます。自動変換結果は 1 件ずつ人手で校正しておらず、すべてのローマ字表記習慣に対応するものではありません。
- 重み：初級 300、中級 200、上級 100、等級なし 10。これは学習等級による並べ替えで、実際の語頻度ではありません。コンパクト版は等級付き語句と例から重み上位 10,000 組を取ります。同重みはコード、語句の順に並べて結果を再現可能にします。「語句、コード」の重複は最大の重みを残します。
- 両バージョンともプロジェクト既存の韓国語例（重み 1,000）を追加し、`hangugeo` → `한국어`、`annyeonghaseyo` → `안녕하세요` などの一般的な入力を含みます。

## 来歴と検証

本ディレクトリは変換結果とライセンスのみをパッケージに含めます。ビルドスクリプトは `tools/build_dictionaries.py` にあり、`dictionary-manifest.json` に記録された URL から固定リビジョンのソースデータを取得し、バイト数と SHA-256 を検証したうえで上記の規則により 4 つの辞書を再生成し、マニフェストの SHA-256 と照合します。したがって変換はリポジトリ内で再現できます。ソースデータは引き続き再配布せず、上記のリンクから各自取得してください。実行方法は `python Dicts/tools/build_dictionaries.py`（再生成して検証）。`--check` を付けると固定リビジョンのソースデータで全辞書を再生成し、`dictionary-manifest.json` の SHA-256 とバイト単位で照合する検証のみを行い、本ディレクトリは変更しません。変換ライブラリは `pykakasi==2.3.0` と `korean-romanizer==0.28.0` に固定し、取得した入力は再実行を速くするためにキャッシュします（キャッシュ先は下表の `DEFAULT_CACHE`。いつでも削除できます）。

### スクリプトの設定項目

重みと規模の設定は `build_dictionaries.py` の先頭にまとまっており、値を変えると辞書の規模と並びの傾向が変わります：

| 定数 | 現在の値 | 役割 |
| --- | --- | --- |
| `JAPANESE_COST_BASE` | `40000` | 日本語の重み = この値 − Mozc のコスト。コストが低いほど上位。値を上げると日本語全体の重みが上がります |
| `JAPANESE_SAMPLE_WEIGHT` | `50000` | プロジェクトの日本語例に与える重み。`japanese_sample.tsv.txt` に書かれた 100/80/50 を上書きします |
| `JAPANESE_COMPACT_SIZE` | `30000` | `japanese_mozc_common` に残す件数。重みの降順、同重みはコード→語句の順で上位 N 件 |
| `JAPANESE_ALLOWED` | ひらがな `U+3041–U+3096`、カタカナ `U+30A1–U+30FA`、`ー` `U+30FC` | 読みに許可する文字。それ以外は仮名以外として行ごと除外 |
| `JAPANESE_CODE` | `^[a-z'-]+$` | ローマ字コードに許可する文字。一致しない読みは破棄 |
| `KOREAN_LEVEL_WEIGHT` | 초급 `300`、중급 `200`、고급 `100`、等級なし（`없음` または記載なし）`10` | 語彙等級ごとの重み |
| `KOREAN_SAMPLE_WEIGHT` | `1000` | プロジェクトの韓国語例に与える重み。`korean_sample.tsv.txt` の 100 を上書きします |
| `KOREAN_GRADED_MIN_WEIGHT` | `100` | `korean_nikl_common` の下限。この重み以上の等級付き項目だけが上位 N 件の対象になります |
| `KOREAN_COMPACT_SIZE` | `10000` | `korean_nikl_common` に残す件数 |
| `KOREAN_WORD` | `^[가-힣]+( [가-힣]+)*$` | 見出しは韓国語音節と単一スペースのみ。ハイフン接辞・単独字母・非韓国語・二重スペースは除外 |

その他の設定：`DEFAULT_CACHE`（入力キャッシュ先。既定は `Temp/dict-cache`）、`JAPANESE_SAMPLE` / `KOREAN_SAMPLE`（例ファイルのパス）、`HEADERS`（各出力の 3 行の `#` コメント。SHA-256 に含まれます）。定数を変更すると出力が変わるため、スクリプトを再実行し、`dictionary-manifest.json` の `outputs` と `statistics` も更新してください。

公開ファイルは `dictionary-manifest.json` で照合できます：`generator` は生成スクリプト（`Dicts/tools/build_dictionaries.py`）、`outputs` は各辞書の項目数と SHA-256、`bytes` はバイト数、`sources` と `source_revisions` は上流ファイルの URL とコミット番号、`conversion_packages` は当時使用した変換ライブラリのバージョン、`statistics` はフィルタ統計を記録します。ハッシュは `#` コメント行を含むファイル全体に対して SHA-256 で計算します。

変換ではプロジェクトの少数の例のみを補足として使用し、その検証値は `local_supplements` に記録しています。ライセンスと表示要件は変換方法やスクリプトの場所によって変わらず、上記の各節が引き続き適用されます。

取り込みと設定の手順は [MULTILINGUAL-JP.md](../MULTILINGUAL-JP.md) を参照してください。同じ言語では 1 つのバージョンを選べばよく、完全版とコンパクト版を同時に読み込む必要はありません。
